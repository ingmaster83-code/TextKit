What this tool does

Track down why pasted text mysteriously fails. Your text is not uploaded.

  • Detects: zero-width characters (200B, 200C, 200D, 2060, FEFF), unusual spaces (NBSP, ideographic, thin), soft hyphen, bidi controls (LRM, RLM, LRO, RLO, isolates), Hangul fillers (3164 ...), Braille blank, tag characters, control characters and the replacement character (�)
  • Table: line:column, code, name, kind, risk (low to critical), context and counts by kind
  • Cleaning: remove all (space-like ones become ASCII spaces), convert only space-like ones, or mark with [U+XXXX] without removing
  • Options to treat ZWJ / variation selectors in emoji as normal and to ignore a leading BOM

💡 Tips

  • If a pasted password, API key or URL fails, check for a zero-width space.
  • Bidi controls in source code or file names can make the visible text differ from the real content, which is dangerous.
  • The Hangul filler looks like an empty name but passes whitespace checks; add this check to nickname validation.

Frequently Asked Questions

Does removing ZWJ break emoji?

Yes. Combined emoji such as 👨‍👩‍👧 are joined with ZWJ and fall apart without it, so ZWJ next to emoji is treated as normal by default.

Does it remove ordinary spaces too?

No. Normal spaces (U+0020), tabs and line breaks are untouched; only unusual spaces are targeted.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
