What this tool does

Fix line-ending problems between Windows (CRLF) and Linux / macOS (LF) in the browser. Your file is not uploaded.

  • Analysis: counts of LF, CRLF and CR, dominant ending, mixed endings and where they are, final newline, BOM, trailing whitespace
  • Conversion: unify to LF, CRLF or CR, or analyse only
  • Cleanup: add or remove the final newline, trim trailing whitespace, add or remove the UTF-8 BOM
  • Input: choose a file (analysed as the original bytes) or paste text (the browser normalises it to LF); copy or download the result

💡 Tips

  • The browser turns pasted line breaks into LF. Use 'Choose a file' to find out whether a file really uses CRLF.
  • Shell scripts and Dockerfiles must use LF; with CRLF you get a 'bad interpreter ^M' error.
  • If Git warns about line endings, also check text=auto and eol in .gitattributes.

Frequently Asked Questions

What is the difference between CRLF and LF?

CRLF (\r\n, two bytes) is the Windows line ending and LF (\n, one byte) is used by Linux and macOS. Mixing them makes diffs noisy and can stop scripts from running.

Does it handle large files?

Tens of MB work as far as browser memory allows, but only the start of the result may be shown on screen, so use the download button.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
