Glob & .gitignore Pattern Tester

Enter patterns and a list of paths to see which paths match and which rule decided, in a table. Supports minimatch-style globs (**, *, ?, braces, character classes, ! exclusion) and .gitignore semantics (last matching rule wins, directory-only slash, root anchoring), and shows each pattern converted to a regular expression.

What this tool does

Check that a pattern behaves as intended before you change build config or .gitignore. Your input is not uploaded.

  • glob: *, **, ?, [abc] / [!abc] / [a-z], {js,ts}, {1..3}, leading ! to exclude, # comments, dotfile and case options
  • .gitignore: a name without a slash matches at any depth, a leading / anchors to the root, a trailing / matches directories only, the last matching rule wins and a file inside an ignored folder cannot be re-included
  • Results: per-path match and the deciding rule, plus the matched paths to copy
  • A pattern → regex table to see how it works

💡 Tips

  • * never crosses a /; use ** to span folders.
  • In .gitignore build ignores any build at any depth, while /build ignores only the one in the root.
  • Once a folder is ignored you cannot re-include files inside with !; ignore its contents (build/*) instead.

Frequently Asked Questions

Does it support extglob such as @(a|b)?

No. Use {a,b} braces or several patterns instead.

Can the result differ from Git?

The core rules are implemented but not every exception (already-tracked files, global ignore files). Confirm with git check-ignore -v.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
