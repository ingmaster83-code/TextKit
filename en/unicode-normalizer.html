Unicode Normalizer (NFC · NFD · NFKC · NFKD)

Convert text that looks identical but has different code points (composed vs decomposed Hangul, two forms of é, fullwidth, enclosed and ligature characters) to NFC, NFD, NFKC or NFKD. See a length and byte table for all four forms and the list of changed characters, and check whether two texts are equal after normalisation.

What this tool does

Fix search, comparison and de-duplication that fail on text that looks the same. Your text is not uploaded.

  • Forms: NFC (compose), NFD (decompose), NFKC (compatibility compose), NFKD (compatibility decompose)
  • Comparison table: code points, UTF-16 length, UTF-8 bytes and equality with the input per form
  • Changed characters: code points before and after with the kind (decomposed, composed, replaced), including grapheme-level composition
  • Compare with text B: finds a line or word that becomes equal under NFC / NFKC
  • Situation notes for decomposed Hangul (U+1100 jamo) and information loss under compatibility forms

💡 Tips

  • Normalise user input to NFC before storing or comparing so search and duplicate checks stay consistent.
  • Hangul file names made on macOS can show split jamo on Windows or the web; convert them to NFC.
  • NFKC reduces meaning (① → 1, ㈜ → (주), ﬁ → fi), so use it for identifiers and search keys only.

Frequently Asked Questions

Should I use NFC or NFD?

NFC is generally recommended for storage and comparison. NFD appears in the macOS file system and as an intermediate step, for example when stripping accents.

Does normalising change the character count?

Code points can change: a Hangul syllable becomes 2-3 jamo in NFD and e + combining accent becomes one é in NFC. What people see (graphemes) stays the same.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
